# G3 生产变化与账户边界

G3 从 `btc-F3-live-flex/btc-F3-live` 的公开源码派生。当前比较本金是25U，发布 `config.json` 的 `capital_usdt` 和 `max_loss_usdt` 仍是 `null`，必须由用户先填写。交付只进行了离线验证，未启用真钱账户，未下单，未安装或启动服务器服务，未修改旧F3目录。

## 调度与断线处理

- F3只在北京时间09:00评估新入场；G3全天每个完整分钟最多产生一个新信号。时间戳使用最新完成分钟的边界，刚初始化时处于分钟中间则等待下个边界。错过数小时也只检查当前边界，不遍历旧分钟。
- 已结算资金费仍至少滞后一整分钟才可用于信号。通过后等待下一分钟，重新检查当前资金费、实际费率、可用资金、最小数量、配平和风控条件。原到期后60秒TTL保留，超过TTL不下单。
- 任何本轮公开或私有请求/核对失败都丢弃待入场信号，并清除资金费缓存的入场许可。资金费读取失败时可继续处理已有仓位的风险退出，但本轮不允许开启一组新仓位。下一轮重新读取当前资金费、私有账户和公开行情。
- 原执行器在计划建立后的下一轮才发送第一腿。G3对尚未产生任何订单intent的旧计划也执行失效处理，防止恢复后直接发送旧计划。首次发单前再次检查资金费/费用门槛与TTL。
- 已持久化订单intent、已经发送或结果未知的请求不被上述丢弃动作删除。仍使用原订单ID查询、核对真实成交与资金费账单；两腿已开始的风险恢复继续由原执行器管理，不重复补发新ID。进程重启也执行同样的未发送计划丢弃规则。
- 交易端每轮自行读取公开行情与私有账户。代理看守状态不能给交易端授予入场许可，不能跳过账户或行情核对。

这里的“每分钟一次”是新信号评估频率；下一分钟以及首腿实际发送前的必要复核仍会执行。轮询默认10秒，信号时间戳对齐分钟边界，不代表交易所会在整分即时收到订单。

## 保留的F3规则

`g3core/strategy.py` 的 `RULES` 所有值与F3相同；`entry_signal`、`plan_entry`、`evaluate_position`、`valuation` 的经济计算未更改。唯一时间窗口改动在新入场调度，资金费恶化退出仍要求持有至少7天，并在北京时间09:00按日累计3次不利检查。保证金、残余敞口、单组损失、净值回撤及绝对亏损条件仍按每轮当前账户检查。资金费兑换仍等待一分钟，并在到期时用当前可用且符合条件的金额复核。

全仓2倍、独立子账户、现货BTC加币本位空头、真实手续费与成交对账、未知订单不重发，以及停服空仓后经账单验证的 `sync-capital` 机制保留。追加资金不会提高用户填写的绝对亏损限额，不清除风控停止，不记为利润。

## 名称与隔离

| 项目 | G3值 |
|---|---|
| 版本与账本策略标识 | `G3-live-1` |
| Python包 | `g3core` |
| 安装目录 | `~/btc-G3-live` |
| 交易服务 | `btc-G3-live.service` |
| 本地账本 | `~/btc-G3-live/var/live/state.sqlite3` |
| 自有账户登记 | `~/.local/state/btc-G3-live/accounts/` |
| 订单客户端ID前缀 | `g3` |
| 人工确认 | `ARM G3 REAL MONEY`、`FLATTEN G3`、`SYNC G3` |

账户UID哈希仍为原 `sha256('live:'+uid)`；共享锁与独占登记仍使用既有 `btc-v53-live` 命名空间，确保F3、v53与G3不能因为换名字而同时操作同一账户。**不能把共享锁改成G3独立锁来绕过互斥。** 代码和配置完整哈希仍在启用时写入身份，不能靠编辑旧身份哈希或版本字段完成升级。

## 当前F3子账户不被自动接管

本包是独立交付，不是对运行中F3的原地升级。它不要求用户现在新建第三个子账户，也不会自动把当前F3账户登记改成G3。如果准备复用现有F3子账户，须另行核对原服务是否停止、真实持仓、未决/未知订单、账单与两腿余额、原本金/追加资金、损益/峰值/冷却和身份登记，再制定受控迁移步骤。本包没有这样的迁移工具。

只要发现该UID的F3登记或其他策略共享登记，G3拒绝启用；复制F3账本到G3目录也不会通过身份检查。保留原账本、密钥和登记，不能删绑定文件或修改版本/哈希来绕过。暂停、停止服务或零持仓本身均不等于迁移核对已经完成。

## 文件变化索引

- `g3core/strategy.py`：增加 `entry_decision_minute` / `entry_signal_due` 两个纯调度函数，09:00退出函数保留。
- `g3core/runtime.py`：分钟信号、失败/重启失效、恢复后当前公开/私有核对、首腿前复核及TTL。身份失败在任何状态写入前退出。
- `g3core/config.py`：G3版本/服务/包/自有登记，显式阻止F3登记接管；保留共享锁与UID哈希。
- `g3core/execution.py`：初始账本添加G3策略标识，计划原因改为分钟信号；其余交易执行算法沿用F3。
- `g3core/store.py`：客户端订单ID改为 `g3` 前缀；账本事务与未知订单核对沿用F3。
- `g3core/capital.py`、`market.py`、`okx.py`、`status.py`、`launch.py`、`deploy/`：对应G3名称与提示；资金同步及适配器算法不变。

离线测试命令：`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`。测试使用合成行情、假API及临时目录；不加载真实密钥或访问真钱账户。离线通过不代表已经验证真实交易所成交或服务器部署。
