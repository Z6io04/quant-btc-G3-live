# 以后怎么追加资金

本版不设固定本金上限，但不会自动使用充值。你选择的是：**充值后手动执行一次同步，核对后增加预算。** 同步命令不转账、不下单、不启动服务。

首次投入先在 `setup-config` 填写，再 `arm-live`。本页只用于已经建立账本后的追加。

## 支持的情况

- G3 空仓、两腿操作结束，无挂单、无未核对订单、无故障，BTC 余额为 0（含零头）。
- 只追加 USDT 到原 G3 子账户的**交易账户**，API 和账户不变。
- 先停止 G3，再划转，最后同步。不要在 G3 运行中先充值。
- 不是从 v53 挪正在使用的资金，不通过本命令提款或转出。

持有组合时先等其正常结束。确实要提前退出，可按日常说明使用 `flatten`，但这会真实平仓，不能把它当作普通充值的必需步骤。

## 每次的操作顺序

**1. 查看状态，并在欧易核对实际账户。**

```bash
python3 "$HOME/btc-G3-live/launch.py" status
```

确保没有组合、没有正在执行的操作、未核对订单为 0、没有故障及 BTC 零头。刚平仓时，继续让服务正常核对成交和账单，确认完成再停止。

**2. 停止 G3。**

```bash
systemctl --user stop btc-G3-live.service
systemctl --user is-active btc-G3-live.service
```

显示 `inactive`。这不停止 v53，也不停止 Mihomo。停服不会平仓，所以先核对空仓。

**3. 在欧易手动将新增 USDT 转入 G3 子账户的交易账户。**

等待到账。资金停留在资金账户不会改变程序使用的交易账户余额。此时不要先启动 G3。

**4. 执行一次资金同步。**

```bash
python3 "$HOME/btc-G3-live/launch.py" sync-capital
```

程序查询真实账单及余额，显示新增金额、原本金、新本金和保持不变的亏损停止金额。确认金额正确后，按提示输入 `SYNC G3`。

例如首次投入 25U，后来转入 10U，核对通过后当前预算为 35U，累计追加为 10U；这 10U 不算策略收益。重复执行不会重复加钱。

只有看到 `passed: true`、`changed: true` 和预期 `capital_usdt` 才表示新增本金已登记。没有新转入时会显示 `changed: false`、`added_usdt: "0"`，原账本不变。

**5. 同步成功后启动 G3，并检查状态。**

```bash
systemctl --user start btc-G3-live.service
python3 "$HOME/btc-G3-live/launch.py" status
```

启动后新的预算参与后续信号和下单计划，不保证立即出现交易。原来的暂停状态若为暂停，同步不会擅自恢复。

## 检查失败怎么办

- 服务仍运行：不要充值或强行继续，先按顺序停服。
- 余额和账单暂不一致：先等欧易账单完整，再重试同步；不要先启动服务。
- 有转出、提现、手动交易、未知账单、BTC 零头或持仓：这不属于本版的空仓 USDT 追加流程，保留账本排查。
- 刚平仓后账单仍未完整核对：保留真实记录，不删除账单绕过检查。
- 已有风控停止：充值不能清掉亏损或恢复交易，`resume` 也不会清除这个停止。
- 离线超过 6 天：不能直接同步，须先核对完整历史，避免漏账。
- 已经在服务运行时充值并触发陌生账单保护：不能用同步命令当“忽略错误”按钮，要保留记录处理原差异。

同一笔入金的账单登记和预算增加在一个数据库事务中保存。中断后重试会先核对，成功保存的入金不会再加一次。原配置、API、历史成交和累计亏损停止金额都不因同步而修改。

本版没有“全部余额自动变成本金”的功能。最初未分配的闲置余额、交易盈利、BTC 和无法证明来源的增量，都不会自动当作本次新增 USDT。
